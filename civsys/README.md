# Civilization Systems 
code2create-7-0 

> **We don't script a civilization. We create the conditions for one to emerge.**

Civilization Systems is an artificial civilization and agent-based simulation laboratory exploring how macro-level social and economic behavior can emerge from the interactions of many individually simple, bounded-rational agents. 

---

## 1. The Problem

Traditional simulation systems often rely on scripted outcomes (e.g., programming a rule like `if drought: migrate`). They use rigid event-to-effect rules and highly simplified agents lacking memory, beliefs, or multi-dimensional relationships.

Conversely, newer LLM-driven agent simulations can become prohibitively expensive at population scale. They are slow, difficult to audit, struggle with deterministic reproducibility, and making thousands of model calls per tick is impractical.

**Civilization Systems explores an alternative approach:**
Can large-scale civilization behavior—such as economic collapse, mass migration, or institutional welfare—organically emerge from deterministic, bounded-rational agents interacting dynamically with their environment and each other?

---

## 2. What We Built

Review 1 implements a highly optimized, pure-Python deterministic simulation engine running a **128×128** procedural world.

**Agents possess highly detailed state:**
* Biological needs (hunger, thirst, health)
* Personality and transient emotions
* Perception and episodic memory
* Beliefs, goals, and skills
* Economic state and bounded inventory
* Multidimensional relationships (trust/affection) and reputation
* Group membership

**The Environment contains:**
* Procedural cellular automata terrain
* Biomes (farms, forests, rivers, resource nodes)
* Dynamic environmental fertility

**The Simulation orchestrates:**
* Resource extraction and production
* Dynamic Markets with supply/demand and Exponential Moving Average pricing
* Social relationship graphs, cohesive communities, and institutional redistribution
* Migration and population metrics
* Causal-event tracking and reproducible experimental branching

## 3. How the World Works Visually

When Civilization Systems runs, you are presented with a 2.5D visual representation of the simulation state.

* **The World**: The civilization is rendered as a top-down / isometric-style lightweight 3D world.
* **The Environment**: Terrain and biomes (grass, forests, farms, water, rocks) visually match the procedural map generated by the backend.
* **The People**: Human agents are rendered as lightweight visual entities/sprites, prioritizing the ability to render hundreds of agents efficiently rather than rendering expensive fully simulated 3D humans.
* **The Camera**: You can explore the civilization spatially across the map.

**Important Architectural Concept:**
> The renderer does not decide what agents do. It merely visualizes what the simulation engine has already decided.

### Visual Separation of Simulation and Assets

The appearance of an agent does NOT determine its behavior. For example, assigning `visual_profile = "worker_01"` only tells the renderer **how the entity should look**. It does not inherently mean the agent's occupation is a worker or their personality is hardworking.

Simulation state independently determines occupations, decisions, relationships, and actions. This strict separation allows us to replace visual assets without altering simulation behavior.

### The World as a Living System

The map is not just a static background—it is part of the simulation state. Terrain has fertility, resources exist in physical locations, and agents extract them. Production alters resource availability, and environmental events modify those conditions. The map is both **what you see** and **the environment the agents live in**.

## 4. What the User Can Actually Do

In the current Review 1 implementation, users can interact with the civilization by:

* **Creating and Starting** a new simulation.
* **Stepping** through simulation ticks.
* **Inspecting an individual agent** to observe their needs, economic state, beliefs, and relationships.
* **Observing metrics** such as population dynamics, food prices, and economic pressure.
* **Injecting events** (like a Drought) to disrupt the environment.
* **Running Experiments** to compare a Control branch against a Treatment branch.
* **Tracing simulated state transitions** to understand *why* an agent made a decision or died.
* **Watching migration** and population shifts happen in real-time.

*(Features like pausing/resuming or changing simulation speed smoothly are planned for the frontend but currently driven by discrete stepping commands).*

## 5. What Happens When You Run It?

Every tick represents one simulated hour. As time passes, the civilization emerges:

```text
Start civilization
      ↓
Agents perceive their surroundings
      ↓
Needs change over time
      ↓
Agents evaluate possible actions
      ↓
Agents act
      ↓
Actions change resources / relationships / economy
      ↓
Markets respond
      ↓
Social groups respond
      ↓
Population changes
      ↓
New state feeds back into future decisions
```

---

## 6. What Output Does the Project Give the User?

Civilization Systems is not about producing a single final score. The system allows users to ask: **"Why did this outcome happen?"** and trace the simulated chain backward.

* **Individual-level outputs**: Agent needs, health, emotions, memories, current actions, inventory, relationships, and location.
* **Social-level outputs**: Cooperation, trust, conflict, group formation, cohesion, and institutional wealth redistribution.
* **Economic-level outputs**: Production yields, supply vs. demand, exponentially shifting food prices, and migration incentives.
* **Population-level outputs**: Population size, deaths, migration shifts, and differences between experimental branches.
* **Investigation outputs**: Causal-event records and deterministic replays of macro metrics over time.

## 7. A Concrete User Scenario

> **Imagine this:**
> You start two identical civilizations. Both begin with the exact same seed and initial conditions. One receives a drought.
> 
> You **don't** tell the agents to migrate. 
> 
> Instead, you watch crop production fall. Food becomes scarce. Hunger increases. Prices rise exponentially. Agents reevaluate their available actions because working the local farm is no longer viable. Migration becomes probabilistically attractive. Some agents leave. Continued scarcity causes health deterioration and population loss.
> 
> The interesting part is not the drought itself. It is watching the chain of consequences emerge entirely unscripted.

*(Note: The exponential pricing highlights the scarcity-price feedback loop, though market ceiling stability is an area for future refinement).*

## 8. What Can Someone Learn From It?

Civilization Systems is an experimental artificial society. Its purpose is to explore mechanisms of emergence, not to make validated predictions about real-world populations. It helps answer:

* How can environmental shocks propagate through an economy?
* How can individual decisions create population-level migration?
* How does scarcity affect prices and behavior?
* How do relationships affect cooperation and institutions?
* How can small initial changes produce vastly different large-scale outcomes?

### Why This Is Useful
* **Researchers**: A controllable environment for experimenting with complex systems, deterministic reproducibility, and agent-based modeling.
* **Students**: A visual way to understand probability, feedback loops, and social simulation.
* **Educators**: An interactive demonstration of how local rules create global behavior.
* **Developers & AI Researchers**: A substantial reference implementation for bounded rationality, causal traceability, and full-stack systems architecture.
* **Curious Users**: A way to watch an artificial civilization develop and simply ask, *"What happens if I change the conditions?"*

# TECHNICAL ARCHITECTURE

## 9. How the Renderer Works

The renderer is built to visualize hundreds of agents efficiently by prioritizing simulation fidelity over AAA graphical complexity.

```text
Simulation State
      ↓
FastAPI / WebSocket transport
      ↓
React + Zustand
      ↓
React Three Fiber
      ↓
Three.js
      ↓
2.5D Civilization World
```

* **Python Simulation** calculates the actual world and agent state.
* **FastAPI** exposes that state via REST and WebSocket.
* **React** manages the UI.
* **Zustand** manages frontend simulation state buffers.
* **React Three Fiber / Three.js** performs the actual 2.5D rendering.
* **React Flow** and **Recharts** handle investigation/causal UI and metrics.

### Where the World is Rendered

The visualization components exist in the frontend source:


## 10. Simulation Pipeline

The master loop (`SimulationEngine.step()`) executes a strict 17-step sequence per tick:

1. **World**: Runs environmental cycles.
2. **Perception**: Updates agent FOV spatial data.
3. **Needs**: Decays biology (hunger/thirst/health).
4. **Emotions**: Transient emotional drift.
5. **Goals**: Evaluates temporary goals against Needs.
6. **Decisions**: Softmax utility scoring to select an Action.
7. **Actions**: Resolves physical world interactions.
8. **Interactions**: Resolves social actions and updates graph edges.
9. **Economy**: Aggregates macro supply/demand and recalculates prices.
10. **Social**: Propagates local social influence.
11. **Groups**: Clusters relationships into cohesive communities.
12. **Institutions**: Enforces rules (e.g., wealth redistribution).
13. **Culture / Beliefs**: Updates agent beliefs based on prices/memories.
14. **Events**: Mutates world parameters based on active interventions.
15. **Population**: Resolves movement, migration, and deaths.
16. **Metrics**: Snapshots aggregate state.
17. **Causal Ledger**: Serializes state transition records.
18. **Snapshot / Streaming**: Buffers state for WebSocket clients.

---

## 11. Agent Decision Model

Agents operate on imperfect information using the following flow:

```text
Perception → Needs → Emotions/Goals → Utility Scoring → Softmax → Action → Consequence → Memory
```

Candidate actions (e.g., `work`, `eat`, `migrate`) receive utility scores influenced by internal state (hunger), economic conditions (prices), and social context. Softmax provides probabilistic action selection based on a seeded RNG generator, ensuring absolute experiment reproducibility.

---

## 12. Reproducibility & The Causal-Event Ledger

The simulation uses strictly seeded RNG (`np.random.default_rng(seed)`).
* Same seed = identical state trajectory.
* Different seed = divergent outcomes.

Civilization Systems records the exact origin of critical state transitions (e.g., `health_depletion` triggers when biological hunger crosses a mathematical threshold). The causal graph answers *"what simulated state transitions led here?"* rather than attempting scientific causal inference.

## 15. API Reference

The backend exposes the following REST routes:

*   **`POST /api/simulation/create`**: Initializes a new simulation engine (seed, pop size).
*   **`POST /api/simulation/step`**: Advances the simulation state by *N* ticks.
*   **`POST /api/simulation/inject_event`**: Injects an active event (e.g. `DROUGHT`).
*   **`GET  /api/simulation/inspect_agent/{agent_id}`**: Retrieves the deep state profile of an agent.
*   **`GET  /api/simulation/causal_graph`**: Retrieves the temporal causal ledger.
*   **`POST /api/experiments/run`**: Spawns an `ExperimentEngine` to run a dual Control vs. Treatment branch.
*   **`WS   /api/simulation/ws`**: WebSocket Stream for rapid state updates (10Hz).

## 17. Hackathon Demo Flow

1. **Initialize**: Start a civilization and explore the generated world.
2. **Inspect**: Select an agent and view their biological, economic, and social state in the Inspector Panel.
3. **Run**: Advance the simulation ticks and watch economic production begin.
4. **Experiment**: Spawn an isolated Control/Treatment branch.
5. **Intervene**: Inject a `DROUGHT` event into the Treatment branch.
6. **Observe Cascade**: Watch local production drop, food supply dwindle, and prices rapidly inflate.
7. **Observe Decisions**: Watch agents dynamically switch from `work` and `cooperate` to `migrate` as local utilities fail.
8. **Trace**: Inspect the Causal Ledger to view the exact state-transition chain that led to the collapse.
